# Tareas: Datos sintéticos, compactación y verificación profunda (`003-synthetic-data`)

**Entrada**: `specs/003-synthetic-data/` (`spec.md`, `plan.md`, `research.md`, `data-model.md`, `contracts/`, `quickstart.md`, `questions.md`)

**Tests**: obligatorios (constitución VII): cada tarea de código lleva sus tests en la misma tarea; `packages/domain` al 100 % de cobertura antes de cada commit.

**Commits**: un commit por tarea, Conventional Commits en inglés, una línea. Antes de cada commit: `npm run lint && npm run typecheck && npm run test:coverage`.

**Organización**: setup → fundamentos (esquema inyectable, puerto, instantánea) → historias por prioridad (US1 generador, US2 compact, US3 check --deep, US4 esquema de prueba, US5 backup) → cierre. US6 (tooling) va en el setup porque desbloquea `npm run clean && npm run build` desde el principio.

## Formato: `[ID] [P?] [Historia?] Descripción con ruta`

- **[P]**: paralelizable (ficheros distintos, sin dependencia de tareas incompletas)
- **[US1..US6]**: historia de `spec.md` a la que sirve

## Estrategia

1. **MVP** = Fases 1-3: el golden file existe y toda feature posterior tiene contra qué probar; `compact` y `check --deep` llegan después sobre la misma instantánea.
2. Cada tarea termina con `lint`, `typecheck` y `test:coverage` en verde y su commit; nunca se acumulan cambios entre tareas.
3. La fixture `synthetic-v1.jsonl` se genera una sola vez (T015) y no se regenera salvo cambio justificado del generador en un commit propio (decisión (i) del prompt).
